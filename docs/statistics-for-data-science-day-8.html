Random Variables and Probability Distributions

From "what's the chance of this one thing" to modeling every possible outcome at once.

By Shikhar · Series continued · ~15 min read

In Day 7, we learned to compute the probability of one specific event. Questions like "what's the probability of rolling a 5?" or "what's the probability this email is spam?"

But data science rarely deals with single, isolated events. The questions that actually come up tend to look more like this: how many items does a typical Amazon shopper add to their cart before checking out, and what's the probability it's more than 10? How long does a Netflix user browse before picking something, and what's the probability they give up within 90 seconds? How many people will click on this ad today?

Notice the shift. We're no longer asking about one outcome. We're asking about the entire range of possible values, and the probability attached to each one. Answering questions like that takes two new ideas: random variables and probability distributions.

What is a random variable?

A random variable is a variable whose value is the numerical result of a random experiment. It's a way of attaching numbers to outcomes so you can actually do math with them.

Think of it as a function. It takes a raw outcome, like "the user clicked," and turns it into a number, like 1 for a click and 0 for no click. Once outcomes become numbers, you can compute averages, spreads, probabilities, all the tools we've built up over this whole series.

Notation

Random variables get a capital letter, like X or Y. A specific value that variable takes gets a lowercase letter, like x. So P(X = x) reads as "the probability that the random variable X takes the value x."

Random variables come in exactly two flavors, and which one you're dealing with changes everything about how you work with it.

Discrete vs. continuous random variables

Discrete random variables take on a countable number of distinct values, usually whole numbers, with real gaps between them. The number of ads a user clicks in a session: 0, 1, 2, 3, but never 1.7. The number of bug reports filed on GitHub in a day. The number of support tickets Uber receives per hour. The result of rolling a die: 1 through 6, nothing in between.

Continuous random variables can take any value within a range, decimals and fractions included, with no gaps at all. The time a Netflix user spends browsing before picking a title could be 23.7 seconds or 104.2 seconds. A webpage's exact load time in milliseconds. The temperature an IoT sensor records on a server rack. A user's exact session length on Spotify.

The core difference

With a discrete variable, you can list every possible value and ask "what's the probability of exactly this one?" With a continuous variable, there are infinitely many possible values, so the probability of hitting any single exact value is zero. You have to ask about a range instead. This one distinction drives everything that follows in this article.

What is a probability distribution?

We just defined a random variable as a function that maps outcomes to numbers. Say X = "number of items added to a cart" can take values 0, 1, 2, 3, and so on. But knowing which values are possible is only half the story. The more important question is: how often does each value actually happen?

That's exactly what a probability distribution tells you. It's a complete description of a random variable: it lists every value the variable can take, and assigns a probability to each one. Together, those probabilities paint a full picture of how the variable behaves.

Building your first distribution from scratch

Let's build one from the simplest experiment there is: rolling a single fair die. Define X as the face value shown after one roll. X can take the values {1, 2, 3, 4, 5, 6}, and since the die is fair, every outcome is equally likely.

x (value)P(X = x)
11/6 ≈ 0.167
21/6 ≈ 0.167
31/6 ≈ 0.167
41/6 ≈ 0.167
51/6 ≈ 0.167
61/6 ≈ 0.167
Total1.000

This table is the probability distribution. Two things about it are worth noticing right away. First, every probability sits between 0 and 1, nothing is impossible, nothing is guaranteed. Second, all the probabilities add up to exactly 1.0, since the distribution has to account for every possible outcome, no exceptions.

That second point isn't just a technicality. It's the normalization rule, a direct consequence of the basic axioms of probability, and it's the one requirement every valid probability distribution must obey, no matter how simple or complicated it gets. (It's a different idea from the "law of total probability" you may see elsewhere, which is a specific technique for computing a probability by summing over conditional probabilities. Similar spirit, different tool.)

The two paths forward

Here's where the road splits, based on what kind of random variable you're working with. If X is discrete, you describe its distribution with a Probability Mass Function, or PMF. If X is continuous, you use a Probability Density Function, or PDF. Both exist to describe the same thing, a distribution's shape, but they work in very different ways because discrete and continuous data behave so differently. Let's take each in turn.

Probability Mass Function (PMF)

For discrete random variables, the distribution is described with a Probability Mass Function, or PMF: a function that gives you the exact probability of each possible value.

P(X = x)
The probability that random variable X takes the exact value x. Properties: 0 ≤ P(X=x) ≤ 1 for every x, and ∑ P(X=x) = 1 across all of them.

Think of a PMF as a complete lookup table. For every possible value, it hands you a probability. And if you add up every probability in the table, you get exactly 1, because something has to happen.

Example: Uber support tickets per hour

Say Uber's data team looks at a year of data and finds this distribution for the number of rider support tickets received per hour during peak time:

Tickets per hour (x)012345
P(X = x)0.050.150.300.250.150.10

Check that it's a valid PMF first: 0.05 + 0.15 + 0.30 + 0.25 + 0.15 + 0.10 = 1.00. Good, it holds up.

Now you can answer questions directly. The probability of getting exactly 2 tickets in an hour is P(X = 2) = 0.30, or 30%. The probability of getting more than 3 is P(X > 3) = P(X=4) + P(X=5) = 0.15 + 0.10 = 0.25, or 25%.

pythonimport matplotlib.pyplot as plt # Uber support tickets per hour, the PMF values x_values = [0, 1, 2, 3, 4, 5] pmf_values = [0.05, 0.15, 0.30, 0.25, 0.15, 0.10] # Verify it's a valid PMF print(f"Sum of PMF = {sum(pmf_values):.2f}") # should be 1.00 fig, ax = plt.subplots(figsize=(8, 4)) ax.bar(x_values, pmf_values, color='steelblue', edgecolor='white', width=0.5) ax.set_xlabel('Number of Support Tickets (x)') ax.set_ylabel('P(X = x)') ax.set_title('PMF: Uber Support Tickets per Hour') plt.show()

This is the PMF doing exactly what it's built for: turning uncertainty into numbers you can actually act on.

Example: GitHub bug reports per day

GitHub's internal engineering team tracks how many bug reports get filed per day for a given product. From 200 days of data, they observe: P(0 bugs) = 0.10, P(1 bug) = 0.25, P(2 bugs) = 0.35, P(3 bugs) = 0.20, P(4 bugs) = 0.10.

This lets the team answer something that matters for sprint planning and on-call scheduling: on any given day, what's the probability of having more than 2 bugs to fix?

First, check the PMF is valid: 0.10 + 0.25 + 0.35 + 0.20 + 0.10 = 1.00. Good. "More than 2 bugs" means P(X > 2), so add up X=3 and X=4: P(X > 2) = 0.20 + 0.10 = 0.30. And "at most 1 bug" means P(X ≤ 1), so add X=0 and X=1: 0.10 + 0.25 = 0.35.

Probability Density Function (PDF)

Here's the problem: what happens when you try to apply the PMF idea to a continuous random variable, like page load time?

Imagine asking "what's the probability a page loads in exactly 312 milliseconds?" The answer is essentially zero. Not because it can't happen, but because on a continuous scale, hitting any single infinitely precise value has vanishing probability. If you tried to bar-chart every possible value the way we just did for discrete data, you'd end up with infinitely many bars, every single one with a height of zero, telling you absolutely nothing.

The fix is the Probability Density Function, or PDF. Instead of assigning probability to individual points, it assigns probability to a range.

The key insight

For a continuous random variable, P(X = an exact value) is always 0. But P(a ≤ X ≤ b) equals the area under the PDF curve between a and b. Probability lives in intervals, not at single points.

P(a ≤ X ≤ b) = area under f(x) between a and b
Two properties: f(x) ≥ 0 everywhere, and the total area under the whole curve equals 1.

The height of the PDF curve at any point is called the density, and it is not itself a probability. It tells you how tightly packed the probability is around that point. A tall peak means values near there are common. A flat stretch means values are spread thin.

Example: Netflix browse time before selecting a title

Netflix's data shows that the time X, in seconds, a user spends browsing before choosing a title roughly follows an exponential distribution. Most users pick something quickly, and a small fraction browse for a long time. The curve starts high and falls off steeply to the right.

Cumulative Distribution Function (CDF)

The PMF and PDF are great at answering pin-point questions: "what's the probability of exactly 3 fraud flags" or "what's the probability a user browses between 30 and 60 seconds." But in the real world, data scientists more often need a different kind of question answered: what's the probability that X is at most some value? What fraction of customers churn within the first 30 days? What percentage of transactions are below a certain amount? What's the probability a model responds in under 200ms?

That's exactly what the Cumulative Distribution Function, or CDF, answers.

F(x) = P(X ≤ x)
The probability that X takes a value less than or equal to x. Works the same way whether X is discrete or continuous.

The CDF works for both discrete and continuous variables. For discrete variables, F(x) is the sum of every P(X = k) for k at or below x, you're adding up the PMF bars from the left up to x. For continuous variables, F(x) is the area under the PDF from negative infinity up to x, you're accumulating area as you sweep right along the curve.

A CDF always has the same basic shape: it starts at 0 (nothing has happened yet), climbs as x increases, and eventually reaches 1.0 (every outcome is now accounted for). That S-curve shape is instantly recognizable once you've seen it a few times.

Building the CDF from the PMF: Uber tickets example

Take the Uber support ticket PMF from earlier. The CDF is built by accumulating those probabilities left to right:

x (tickets)P(X = x)F(x) = P(X ≤ x)
00.050.05
10.150.05 + 0.15 = 0.20
20.300.20 + 0.30 = 0.50
30.250.50 + 0.25 = 0.75
40.150.75 + 0.15 = 0.90
50.100.90 + 0.10 = 1.00

Now you can read off answers instantly. There's a 50% chance of getting 2 or fewer tickets in an hour, since F(2) = 0.50. There's a 90% chance of getting 4 or fewer, since F(4) = 0.90.

pythonimport numpy as np x_values = np.array([0, 1, 2, 3, 4, 5]) pmf_values = np.array([0.05, 0.15, 0.30, 0.25, 0.15, 0.10]) cdf_values = np.cumsum(pmf_values) # running total builds the CDF print(f"P(X <= 2) = {cdf_values[2]:.2f}: probability of 2 or fewer tickets") print(f"P(X <= 4) = {cdf_values[4]:.2f}: probability of 4 or fewer tickets") print(f"P(X > 3) = {1 - cdf_values[3]:.2f}: probability of more than 3 tickets")
OutputP(X <= 2) = 0.50: probability of 2 or fewer tickets P(X <= 4) = 0.90: probability of 4 or fewer tickets P(X > 3) = 0.25: probability of more than 3 tickets

Reading straight from the CDF column: the probability of 2 or fewer fraud flags per minute is just F(2) = 0.70. No adding required, that's the entire point of having a CDF in the first place, it's already accumulated for you. The probability of more than 3 flags is 1 − F(3) = 1 − 0.90 = 0.10. And the probability of between 1 and 3 flags inclusive is F(3) − F(0) = 0.90 − 0.10 = 0.80.

Seeing them together: PDF and CDF for continuous data

For continuous random variables, the PDF and CDF are two views of the exact same distribution. Plotted side by side, their relationship becomes obvious: wherever the PDF is tall, the CDF is climbing steeply. Wherever the PDF flattens out, the CDF barely moves at all.

pythonimport numpy as np from scipy import stats dist = stats.expon(scale=90) # Read key statistics straight off the CDF median = dist.ppf(0.5) # inverse CDF at 50% p90 = dist.ppf(0.9) # inverse CDF at 90% print(f"Median browse time: {median:.1f} seconds") print(f"90th percentile browse time: {p90:.1f} seconds") print(f"P(user picks within 2 minutes): {dist.cdf(120):.3f} ({dist.cdf(120)*100:.1f}%)")
OutputMedian browse time: 62.4 seconds 90th percentile browse time: 207.2 seconds P(user picks within 2 minutes): 0.736 (73.6%)
Key takeaways

A random variable maps random outcomes to numbers. It comes in two types: discrete (countable values) and continuous (any value in a range). The PMF gives exact probabilities for discrete variables. The PDF describes probability density for continuous variables, where probability is the area under the curve, never the height at a single point. The CDF accumulates probability up to any value and works for both types, and it's often the most practically useful of the three for answering real business questions. Together, these three tools give you a full mathematical portrait of a dataset.

Quick check

Four questions to test whether this stuck.

Is "the number of typos in a blog post" discrete or continuous? What about "the exact time between two consecutive typos"?

Typos are discrete: you can have 3 or 4, never 3.5. Time between typos is continuous: it could be 12.3 seconds or 12.34 seconds, with no gaps between possible values.

A PMF has P(X=1)=0.2, P(X=2)=0.5, and P(X=3) unknown. What must P(X=3) be?

0.3. Every valid PMF has to sum to exactly 1 across all its values, so P(X=3) = 1 − 0.2 − 0.5 = 0.3.

Why is it meaningless to ask "what's the probability a Spotify session lasts exactly 47.000000 minutes"?

Because session length is continuous, and a continuous variable has infinitely many possible exact values. The probability of landing on any single one of them is 0. The question that actually has a real answer is something like "what's the probability the session lasts between 46 and 48 minutes," which is the area under the PDF over that range.

You're given a CDF where F(10) = 0.4 and F(20) = 0.75. What's P(10 < X ≤ 20)?

0.35. Subtract the smaller cumulative probability from the larger one: F(20) − F(10) = 0.75 − 0.4 = 0.35. That's the whole appeal of a CDF: once you have it, ranges become simple subtraction.
